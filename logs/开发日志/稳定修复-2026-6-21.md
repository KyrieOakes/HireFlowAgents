# 稳定修复 — 2026-6-21

## 本次改动概述

本次主要完成项目产品化稳定性修复和文档同步，重点解决真实联调中暴露的前端交互、简历解析、匹配失败和面试表达材料问题。

核心结果:
- 前端工作台完成视觉美化，统一毛玻璃、卡片、动效和详情弹层体验。
- 简历解析从“完全依赖 LLM”升级为“LLM + 原文规则解析 + 乱码/语义错位防线”。
- 多候选人解析不再触发整页白屏 loading。
- Match Agent 遇到 LLM 输出截断时不再让整个 Top 5 匹配接口 500。
- 测试从 44 个增加到 49 个，覆盖新增的简历解析和匹配兜底问题。
- 面试准备文档新增 4 个真实 Bug 解决案例，方便面试时按“现象、根因、解决、表达”讲述。

关键策略:
- 姓名、邮箱、电话不完全信任 LLM，优先从原文确定性抽取。
- 教育、项目、实习、技能按常见中文简历段落结构解析。
- LLM 输出中的 JSON 残片、转义碎片、韩文乱码、联系方式碎片会被过滤。
- 用户手动填写的候选人显示名保持不变，避免解析结果误覆盖。

### 4. 多候选人解析全页 loading 修复

| 文件 | 说明 |
|---|---|
| `frontend/pages/resumes.tsx` | 拆分首次加载 `loading` 与后台同步 `refreshing` |

修复前:
- 任一候选人解析完成后调用 `loadCandidates()`。
- `loadCandidates()` 设置全局 `loading=true`。
- 页面直接返回“加载中...”，导致其他解析按钮被卸载。

修复后:
- 首次进入页面才使用整页 loading。
- 解析完成后先局部更新当前候选人卡片，再后台刷新列表。
- 多个候选人可以连续解析，互不打断。

### 5. Match Agent 输出截断与接口 500 修复

| 文件 | 说明 |
|---|---|
| `app/agents/match_agent.py` | 缩短 prompt 输入，限制输出长度，增加 LLM 失败兜底评分 |
| `tests/test_match_agent.py` | 新增 LLM 输出截断回归测试和 prompt 长度限制测试 |

根因:
- 本地模型在结构化输出时超过 `max_tokens=2047`。
- LangChain/OpenAI 解析阶段抛出 `LengthFinishReasonError`。
- `/jobs/{id}/match?limit=5` 返回 500，前端显示 `Failed to fetch`。

修复后:
- 项目描述、RAG 证据、技能列表、JD 要求都做截断。
- `strengths`、`risks`、`evidence`、`summary` 强制简洁。
- 单个候选人精排失败时，使用技能重合度、项目、教育、经验生成规则兜底评分。
- 批量匹配不会因为一个候选人失败而整体失败。
