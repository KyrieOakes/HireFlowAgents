# JSON 解析与中文强制 — 2026-06-21

## 本次改动概述

修复面试评价和邮件草稿的前端显示问题：LLM JSON 解析失败导致前端显示原始 JSON 文本。强制所有 Agent 中文输出。

## 系统流程图

```
用户点击"生成评价/邮件"
    │
    ▼
Agent 调用 LLM (DeepSeek)
    │
    ▼
LLM 返回 (可能是畸形 JSON)
    │ 例如: {key: value, status: resolved}
    │       (key无引号, value无引号, 结构错误)
    ▼
parse_json_response() — 5 层策略
    ├─ 策略1: json.loads 直接解析
    ├─ 策略2: 去 markdown ``` 标记
    ├─ 策略3: 提取 {...} 对象
    ├─ 策略4: 提取 [...] 数组
    └─ 策略5: 修复常见错误 (key补引号, value补引号)
         │
         ├─ 成功 → 返回 dict → 前端正常显示
         │
         └─ 失败 → fallback 清洗
              regex 去掉 {}[]":, → 只保留可读文本
              → 前端显示纯文本, 不显示原始 JSON
```

## 详细改动

### 1. parse_json_response 策略5 (llm_service.py)
新增 JSON 语法修复:
- 未加引号的值: `status: resolved` → `status: "resolved"`
- 未加引号的 key: `risk_name: value` → `"risk_name": value`

### 2. 解析失败时清洗 (evaluation_agent, email_agent)
之前: fallback 直接把 LLM 原始响应放进 summary/body → 前端显示 `{ "key": "value" }`
修复: 用 regex 去掉 `{}[]":,` 等 JSON 语法字符, 只保留可读文本

### 3. Prompt 中文强化 (evaluation_agent, email_agent)
- 醒目的强制块: `═══════ 【语言强制要求】 ═══════`
- 正误示例: "技术基础扎实" ✅ / "Strong technical skills" ❌
- JSON 格式示例: risk_resolution 必须是数组 `[{...}]` 不是对象 `{...}`

### 4. 前端类型匹配
InterviewEvaluation: summary(string), concerns(string[]), strengths(string[])
EmailDraft: subject(string), body(string)
后端返回字段与前端类型一致, 不需要额外转换

## 前后对比

| 场景 | 修复前 | 修复后 |
|---|---|---|
| LLM JSON 不规范 | 显示 `{"key": "value"}` | 策略5 自动修复引号 |
| 全部解析失败 | 显示原始 JSON 文本 | 清洗为可读纯文本 |
| 评价语言 | 英文 strengths/concerns | 强制中文输出 |
| risk_resolution | LLM 输出对象 `{}` | prompt 示例引导输出数组 `[]` |
