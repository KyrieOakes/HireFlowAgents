# 解析加固 — 2026-8-1

## 1. 本次改动概述

本轮记录自 2026-6-21《稳定修复》开发日志以来的全部改动，重点解决真实联调中发现的数据重复、候选人姓名错误、面试评价乱码、邮件模板污染和 JD 结构化解析污染问题。

核心结果：

- 匹配结果按“岗位 + 候选人”更新，历史重复记录会被清理，排名不再重复显示同一候选人。
- PDF 简历按视觉顺序提取文本，“个人概述”等章节标题不再被误识别为姓名。
- 候选人列表新增“修改姓名”，人工确认的姓名会同步到数据库和结构化画像。
- 面试评价和邮件改用 Pydantic 结构化输出，失败时返回可读、安全且需要人工审核的兜底内容。
- 邮件会强制使用数据库中的真实姓名，并清理 `title/body` 压平文本、韩文乱码、模板签名和字面量换行符。
- 未批准的历史脏邮件草稿会在读取时自动修复，已批准草稿不会被静默改写。
- JD Agent 增加原文规则解析和乱码过滤，职位 ID、韩文、`\x` 转义、错误年份和字段语义错位不会再进入岗位画像。
- 已解析岗位新增“重新解析”入口，方便修复历史错误结果。
- 后端测试从 49 个增加到 60 个，前端生产构建通过。

| 文件 | 说明 |

安全规则：

- 三项面试分数限制在 1-10。
- 推荐值限制为固定枚举。
- `requires_human_review` 永远强制为 `true`。
- 结构化调用失败时不展示模型损坏原文，不自动做录用决定。

邮件安全规则：

- 数据库姓名是称呼的唯一权威来源。
- 检测到 `候选人姓名`、`你的名字`、韩文或压平字段时，直接使用中文安全模板。
- 所有邮件只是草稿，必须由 HR 人工批准，系统不自动发送。

### 3.6 JD 解析乱码和语义错位修复

| 文件 | 说明 |
|---|---|
| `app/agents/jd_agent.py` | 增加 Markdown 清理、章节切分、编号条目提取、乱码检测、标题/地点回填和技术关键词原文提取 |
| `frontend/pages/jobs.tsx` | 已解析岗位继续显示“重新解析”，允许覆盖历史错误结果 |
| `tests/test_jd_agent.py` | 使用 ByteIntern“AI Agent开发实习生-计算”真实 JD 建立乱码与语义错位回归测试 |

JD 清洗策略：

- 岗位名称优先使用可信模型值；出现职位 ID 或乱码时从 JD 头部回填。
- 职位描述中的编号条目成为岗位职责的权威来源。
- 职位要求按语义分别进入必备技能、优先技能、学历和软技能。
- “202处届”这类没有特殊字符但不在原文中的模型错误会被原文条目替换。
- `热爱编程` 不再错误进入优先技能；只有含“优先/加分”的原文条目进入该字段。
- 技术关键词只有在原文实际出现时才会补入，系统不会凭空编造。

## 5. 下一步计划

5. 为本地模型增加输出质量指标，统计结构化调用失败率、规则回填率和人工修改率。
