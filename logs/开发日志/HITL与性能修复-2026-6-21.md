# HITL 与性能修复 — 2026-06-21

## 本次改动概述

修复 7 个问题: 并行加速、RAG 证据接入、Human-in-the-loop 真实实现、安全性、状态契约一致。

## 系统流程图

```
FastAPI (当前主入口, 性能优先)
    │
    ├─ POST /jobs/upload → /parse → JD Agent → PostgreSQL
    ├─ POST /resumes/upload-file → 文件提取 → Resume Agent → PostgreSQL + Qdrant
    ├─ POST /jobs/{id}/match → 粗筛(pre_screening) → RAG证据 → LLM精排(ThreadPool并行)
    │   └─ evidence_by_candidate 传入 Match Agent (支撑评分)
    └─ GET /jobs/{id}/ranking?limit=N

LangGraph Workflow (HITL入口, 正式架构骨架)
    │
    ├─ POST /workflow/run → JD→Resume→RAG→Match→Ranking→Human Review(interrupt暂停)
    │   └─ PostgresSaver checkpoint 持久化中断状态
    ├─ POST /workflow/{id}/resume → 传审批决定 → 继续执行
    │   └─ approved→END / rejected→回到Match / modified→END
    └─ GET /workflow/{id}/state

性能优化:
  Match Agent (ThreadPoolExecutor, max_workers=5)
    串行: C1(6s)→C2(6s)→C3(6s)→C4(6s)→C5(6s) = 30s
    并行: 5个同时 = ~6s
```

## 详细改动

### 性能 (2项)
| 改动 | 文件 | 说明 |
|---|---|---|
| ThreadPoolExecutor 真并行 | match_agent.py | asyncio.gather 对同步 HTTP 无效, 改用线程池 |
| asyncio.gather 并行简历解析 | resume_agent.py | 同上修复 |

### RAG 修复 (2项)
| 改动 | 文件 | 说明 |
|---|---|---|
| evidence 传入匹配 | matching.py | 匹配前为每个候选人调 search_evidence_for_match() |
| point_id 一致性 | vector_store.py + rag_service.py | store_chunks 接收外部 point_ids, 返回实际ID |

### HITL (3个文件)
| 改动 | 文件 | 说明 |
|---|---|---|
| 真实 interrupt() | nodes.py | human_review_node 用 LangGraph interrupt() 暂停 |
| 条件路由 | workflow.py | approved→END / rejected→match_agent |
| Workflow API | api/workflow.py | POST /run, POST /resume, GET /state |

### 安全 + 契约 (3项)
| 改动 | 文件 | 说明 |
|---|---|---|
| 移除硬编码 API Key | config.py | cloud_api_key 默认值 → "" |
| state 契约统一 | state.py | resume_files → resume_texts |
| 架构标注 | workflow.py | API直调 vs workflow 的关系说明 |

### DeepSeek 适配 (2项)
| 改动 | 文件 | 说明 |
|---|---|---|
| thinking 全模型关闭 | llm_service.py | 所有 DeepSeek 模型 function_calling 都需要关 thinking |
| extra_body 传法修正 | llm_service.py | model_kwargs → 直接传给 ChatOpenAI |
