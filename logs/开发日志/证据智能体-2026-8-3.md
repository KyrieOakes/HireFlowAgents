# 证据智能体 — 2026-8-3

## 1. 本次改动概述

本轮记录自 2026-8-1《解析加固》以来的全部改动。系统在原有确定性
LangGraph 招聘流程中新增了一个受控 ReAct Evidence Agent，使项目具备真实的
Tool Calling、Observation 反馈循环、分层重试、错误升级和前端审计能力。

核心结果：

- Evidence Agent 使用 `reason --> tools --> observation --> reason` 子图动态检索简历证据。
- 模型通过原生 Tool Calling 调用 Qdrant 搜索和证据覆盖率工具。
- Agent 最多执行 3 轮、6 次工具调用，完全相同的工具参数不会重复执行。
- Timeout、连接错误、HTTP 429/5xx 使用指数退避，总尝试 3 次。
- 非法参数作为 ToolMessage 返回给模型修正；连续两次非法调用后交给人工。
- 跨候选人查询和受保护属性查询在访问 Qdrant 前立即阻断。
- 工具重试耗尽后，用户可以选择重试、带警告继续、跳过失败候选人或终止。
- 匹配页新增 Agent 轨迹面板，展示查询、Observation、重试、耗时、覆盖率和停止原因。
- 真实本地模型省略 `candidate_id` 时改由运行时注入，并兼容白名单工具名/字段别名。
- 岗位管理页新增与候选人一致的内联改名，人工标题不会被重新解析覆盖。
- 后端测试从 60 个增加到 71 个，前端生产构建通过。

| `README.md` | 同步 8 Agent 架构、Tool Calling、重试边界、流程图和 API 参数 |

本轮测试中发现一个真实安全规则 Bug：英文受保护属性 `age` 使用子串判断时会
误伤单词 `Agent`。最终改为英文词边界匹配，既保留安全阻断，又避免正常 Agent
开发关键词被误判。

真实网页联调还发现本地模型经常省略 `candidate_id`，旧逻辑把空值误判为跨候选人
访问；部分模型还会生成语义等价的工具名或参数别名。现在身份由可信运行时注入，
只有主动填写其他非空 ID 才阻断；可无损转换的别名会在白名单内规范化，审计轨迹
记录实际执行参数。

新增测试重点覆盖：

- 模型读取第一次 Observation 后改写查询并再次调用工具。
- Qdrant 前两次超时、第三次成功，退避间隔为 0.5 秒和 1 秒。
- top_k 越界时不重复错误请求，而是让 Agent 修正参数。
- 模型省略 candidate_id 时由运行时注入，不再误报越权。
- 本地模型的工具名、维度名、查询字段和数字字符串别名可安全规范化。
- 跨候选人 Tool Call 在访问向量库前立即阻断。
- 工具正常返回空列表时标记证据不足，不误报系统异常。
- 临时错误总尝试三次仍失败时生成四种人工处理选项。
- Next.js 匹配页的 Agent 类型和轨迹面板通过生产构建。
- 岗位创建后可内联改名，重新解析 JD 不会覆盖人工名称。

当前 9 条非阻塞警告来自 Pydantic V2 旧式 `class Config` 和测试客户端兼容性，
不影响功能与测试结果。
